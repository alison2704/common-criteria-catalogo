Índice de clases

Lectura rápida del estándar

Clase → familia → componente → elemento. La clase agrupa un objetivo amplio; la familia organiza un tema concreto; el componente es un requisito seleccionable; y cada elemento numerado (por ejemplo, FIA_AFL.1.1) expresa una parte verificable.

Dependencias: si el componente A depende de B, una implementación de A debe considerar también B o una alternativa jerárquicamente válida. No confundas una dependencia con evidencia de que el sistema realmente la implementa.

Operaciones: assignment, selection, refinement e iteration son espacios que deben concretarse en el perfil, paquete o ST. Un espacio sin resolver puede ser el hallazgo.

Método para el caso de estudio

  1. Delimita el activo y el límite: identifica TOE, TSF, usuarios, interfaces y datos afectados.
  2. Describe el evento observable: qué ocurrió, cuándo, quién lo ejecutó y cuál fue el resultado.
  3. Mapea a SFR: localiza el código más específico y baja hasta el elemento numerado.
  4. Contrasta implementación: separa “no existe”, “existe pero está mal configurado”, “falló” y “no hay evidencia”.
  5. Revisa dependencias y auditoría: una conclusión sólida indica qué requisito relacionado también queda comprometido.
  6. Concluye: redacta causa, impacto, evidencia faltante y control/requisito que lo habría prevenido o detectado.

Plantilla mental de respuesta

Hecho: “El sistema permitió/omitió ___”.

Requisito: “Corresponde a XXX_YYY.n.m porque exige ___”.

Brecha: “No se implementó / se implementó parcialmente / falló ___”.

Prueba: “La evidencia sería ___; si no existe, la confianza queda limitada”.

Relación: “También revisar ___ por dependencia, identidad, registro, tiempo o gestión”.

Advertencias de examen

  • Una alarma o un log no evita por sí mismo el incidente: distingue prevención, detección, respuesta y recuperación.
  • “Usuario autenticado” no significa necesariamente “autorizado para esa operación”.
  • Una dependencia satisfecha no prueba que el requisito principal esté correctamente aplicado.
  • Si el enunciado no permite afirmar algo, marca “evidencia insuficiente” en lugar de inventar una configuración.
